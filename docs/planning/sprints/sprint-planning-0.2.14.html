Sprint Plan 0.2.14 — Recipe Entry Refined

Follow-through on 0.2.13 — fixing real-world UX gaps and completing the recipe flow redesign
📅 Started: June 2026 🎯 9 issues ⚡ 34 points 🔵 Track A: 10 pts polish 🟠 Track B: 24 pts redesign
📋 Context & Goal

Milestone goal: Deliver what 0.2.13 promised but didn't fully achieve — recipe entry surfaces that are first-class, guided experiences that reduce cognitive load. Real-world testing revealed two categories of problems: UI/layout bugs across multiple dialogs, and a fundamental architectural flaw in the recipe form (too long, too many save buttons, no guided path).

  • Track A fixes 5 independent layout/l10n bugs — can be done in any order
  • Track B delivers the hub-and-spoke recipe redesign — stub creation, per-section bottom sheets, tags editing finally working
  • Tags and recipe form redesign are the headline deliverables; polish issues round out the milestone

What changed from 0.2.13: The multi-phase form added structure but kept everything in one scrollable surface. The fix is architectural: a minimal stub creation screen + the existing recipe detail screen as the editing hub, with each section opening a focused, keyboard-aware bottom sheet. No more multi-save-button scrollathon.

🔵 Track A — Layout & Polish
#389
Meal options dialog secondary buttons wrap due to narrow side-by-side layout
1 pt P2

Problem: "Marcar como Cozinhada" and "Editar Refeição Cozinhada" wrap to 3 lines in a side-by-side Row — each button only gets half the dialog width.

Fix: Replace the Row with a Column at recipe_selection_dialog.dart:497. Each button gets full width, 5-line change.

#390
Meal recording dialogs: "Receitas" label wraps, time field labels truncated
2 pts P2

Problem: "Receitas" wraps to 3 lines in EditMealRecordingDialog (missing Expanded). "Tempo de Preparo/Cozimento (min)" truncates to "Temp..." in both dialogs.

Fix: Wrap label in Expanded at edit_meal_recording_dialog.dart:302; shorten prepTimeLabel/cookTimeLabel l10n strings to "Preparo (min)" / "Cozimento (min)".

#391
Android nav bar insets not respected — introduce shared bottom sheet helper
3 pts P2

Problem: Ingredient parser confirm button hidden behind Android nav bar in recipe form screens. recipe_details_screen bottom sheet only handles keyboard inset (viewInsets.bottom) not nav bar (padding.bottom).

Fix: Create showGastrobrainBottomSheet() in lib/core/utils/dialog_utils.dart — bakes in isScrollControlled: true, useSafeArea: true, and combined inset padding. Migrate 2 existing call sites. Add rule to lib/widgets/CLAUDE.md.

Note: This helper is required by #395, #396, and #397 — complete before Track B Phase 2.

#392
Add shopping item dialog overflows horizontally and clips when keyboard open
2 pts P2

Problem: SizedBox(width: double.maxFinite) causes horizontal overflow on some devices. Column(mainAxisSize: MainAxisSize.min) without scroll causes buttons to escape dialog bounds when keyboard opens.

Fix: Remove the SizedBox wrapper; wrap Column in SingleChildScrollView. One file, ~5 lines changed.

#393
Unit names display as raw English strings in ingredient dialogs
2 pts P2

Problem: "piece" appears in Portuguese UI in UnifiedAddSideDialog (pre-fill uses unit.value) and IngredientParserSection (raw string from parser displayed directly). getLocalizedQuantityName() exists but isn't called consistently.

Fix: unified_add_side_dialog.dart:111 — use getLocalizedQuantityName(context, 1.0). parser_review_row.dart:89 — convert via MeasurementUnit.fromString() then localize. Audit other display sites.

🟠 Track B — Recipe Redesign
#394
RecipeSelectionCard: excessive whitespace and detached select button
3 pts P2

Problem: Collapsed card is too tall — chevron in a standalone Row adds ~24px; double SizedBox(height:16) creates 32px dead space between tab bar and list on Recommended tab; "SELECIONAR" button has no visual anchor to the card above it.

Fix: Merge chevron into name row; make second spacer conditional on search field visibility; reduce padding from all(16) to symmetric(h:12, v:10); add Divider above SELECIONAR. Two files, layout-only changes.

#395
Ingredient parser: no feedback after Analisar/manual add, mixed entry types, hidden warning
5 pts P1

Problem (4 interconnected issues):

1. "Analisar" shows no response — results appear silently below fold while keyboard is open.

2. "+ Adicionar manualmente" also silent — repeated taps create duplicate blank entries that can be accidentally saved.

3. Blank manual entries mix into "Analisados (N)" list with inflated count and meaningless "1 –" label.

4. Unresolved warning is the text of a grey disabled button at the bottom — invisible until the user scrolls.

Fix: Add isManual flag to ParsedIngredient; auto-scroll via Scrollable.ensureVisible() after parse/add; disable manual-add when last row is blank; split list into analyzed/manual subsections; style confirm button amber when unresolved; add warning row above button.

#396
Recipe entry hub-and-spoke redesign — replace long form with per-section bottom sheets
13 pts P1

The headline issue. RecipeFormScreen and RecipeEditorScreen are long scrollable forms with multiple "Salvar Alterações" buttons. The 0.2.13 phases added structure but didn't fix the fundamental problem.

New model: Stub (name only) → recipe detail screen as hub → per-section bottom sheets. Detail screen keeps its 4 tabs; each tab gets an edit button; each section opens a focused, keyboard-aware bottom sheet with its own save.

Three phases:

Phase 1 — RecipeStubCreateScreen + edit buttons wired to existing screens as placeholders.

Phase 2 — BasicInfoEditSheet, DifficultyTimeEditSheet, NotesEditSheet, InstructionsEditSheet. All use showGastrobrainBottomSheet() from #391.

Phase 3 — Deprecate RecipeFormScreen and RecipeEditorScreen; clean up navigation.

Dependency: #391 must be done before Phase 2. #397 wires in during Phase 2.

#397
Tags editing bottom sheet for recipe hub
3 pts P1

Problem: Tags have been non-functional for at least one milestone. TagPickerWidget and TagRepository are fully implemented — the missing piece is a proper container with correct data loading.

Fix: Create lib/widgets/recipe_editor/tags_edit_sheet.dart — stateful widget that loads tag types + recipe's existing tags on initState(), renders TagPickerWidget, and saves via tagRepo.setTagsForRecipe(). Wire to Visão Geral tab as part of #396 Phase 2.

Note: Sheet can be built and tested independently; tab wiring is done in #396.
