Issues
#371
Redesign ingredient parser UX/UI as a first-class entry method
13 pts UX / Feature High Risk

Makes the ingredient parser a first-class, trustworthy entry method. Builds on IngredientParserService extracted in 0.2.12. Feeds directly into #370 Phase 4 as the primary input method.

Scope
  • Natural language input with parse preview before commit
  • Graceful fallback to manual entry on parse failure — no silent failure
  • Partial parse: surface uncertain fields for user correction
  • Both EN and PT-BR localized (all parser UI labels and error states)
  • Integrates cleanly into #370 Phase 4
Acceptance Criteria
  • Parser result shown as preview — user confirms or corrects before ingredient is added
  • Failed parse falls back to manual entry form — no silent failure
  • Partial parse surfaces which fields need correction
  • All UI strings localized (EN + PT-BR)
  • Widget tests: successful parse, failed parse, partial parse, manual fallback, cancel
  • Edge case tests: empty input, special characters, very long strings
  • No regression in existing ingredient entry
#370
Redesign recipe creation as a phased, progressive disclosure flow
13 pts UX / Feature High Risk

Redesigns recipe creation as a lighter, guided experience. MVP scope: Phases 1 + 4 only. Phases 2 (Timing), 3 (Tags), 5 (Notes) are deferred — follow-up issues must be created before sprint closes. Depends on #371 being complete before Phase 4 implementation starts.

MVP Scope
  • Phase 1 — Stub: Name + meal type only; recipe is saveable immediately
  • Phase 4 — Ingredients: Uses redesigned parser UX from #371 as primary input
  • Phases 2, 3, 5 → follow-up issues created before sprint closes
Acceptance Criteria
  • Phase 1 form: name + meal type; Save enabled as soon as name is non-empty
  • Recipe stub created from Phase 1 appears in recipe list as a valid, usable recipe
  • Phase 4 uses #371 ingredient parser UX as primary input method
  • Phase 1 data preserved when navigating to Phase 4
  • Both phases localized (EN + PT-BR)
  • Widget tests: Phase 1 save, incomplete Phase 1, Phase 4 add/remove ingredient
  • Edge case tests: save stub with no ingredients, back navigation
  • Existing recipe creation path does not regress
  • Follow-up issues for Phases 2, 3, 5 created in GitHub before sprint closes
